## How to read this list

- Tasks `T001` … are grouped into ordered **groups**. A group starts only when the previous group's gate is green (plan "Gates": `pnpm typecheck`, `pnpm run ci`, the scoped vitest run of the group's specs, and `pnpm effect:check:cli` 0/0/0 for every group that touches `packages/cli/src/mcp/` or `packages/cli/src/check/files.ts`).
- **[P]** marks a task that creates only NEW files, disjoint from every other task of its group; the [P] tasks of a group run in parallel. A task without [P] runs alone, in the listed order. Every task that edits an existing or shared file (`server.ts`, `tools/brief.ts`, `engine.ts`, an existing spec, `biome.json`, `vitest.config.ts`, `main.ts`, `AGENTS.md`, …) is unmarked.
- Every task follows the repo order: **write the failing test first and run it red → implement → `pnpm check` clean (Biome autofix, 0 errors, 0 warnings) → the verify command green**. Tasks that touch Effect code (anything under `packages/cli/src/mcp/`) also run `pnpm effect:check:cli` with 0 errors, 0 warnings, 0 messages gated. A pure move (T002 to T005) has no new behaviour: its guard is the named existing specs, green before and after.
- Paths: Bash takes `/f/projects/eligius/eligian/...`; every other file tool takes `F:\projects\eligius\eligian\...`. Commands below run from the repo root in Bash. `cli/` means `packages/cli/src/`; specs are in `packages/cli/src/__tests__/` unless a path says otherwise.
- **CLI specs resolve `@eligian/language` to its built output.** Run `pnpm -C packages/language build` once before the first CLI spec. **Spawned specs** (`spawnServer`, `bin/cli.js`) `skipIf(!built)`: every task that adds a spawned case runs `pnpm -C packages/cli build` first and checks in the vitest output that those cases ran (passed, not skipped).
- Effect v4 idioms: `Effect.fail` with tagged errors (`Data.TaggedError`, a `_tag`), no `try`/`catch` inside `Effect.gen` (sync or async helpers that catch are plain functions outside the generator, Effect LSP `tryCatchInEffectGen`), `Effect.void`, no `Effect.gen` adapter, `// @effect-diagnostics unstableApiUsage:off` at the top of a module that uses `ai.*` (as `tools/brief.ts:19`). No `console.*` and no `process.stdout` in `brief/*`, `tools/brief.ts` or `check/files.ts` (SC-014). The repo `lib` is ES2020: no `Array#at`, no `Object.hasOwn`.
- **Phase 1 specs are frozen except for the Phase 1 edit list** (plan "Phase 1 edit list", entries 1 to 5). The nine files are `brief-engine`, `brief-file`, `brief-tool`, `brief-tool-defect`, `brief-tool-tree-version`, `brief-tree`, `brief-values`, `mcp-brief-interview`, `mcp-brief-restart` (`.spec.ts`). New tests go in the new spec files named below; the only additions allowed to `brief-file.spec.ts` and `brief-values.spec.ts` are the describes the plan's test plan names (`addition sections`, `scope line`, `S2 names`).
