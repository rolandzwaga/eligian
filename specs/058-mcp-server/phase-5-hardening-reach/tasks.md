## How to read this list

- Tasks `T001…` are grouped into **ordered groups**. A group starts only when the previous group is done (the workflow gates after every group).
- **[P]** = parallel-safe inside its group: the task creates **new files only**, disjoint from every other [P] task of that group. A task that edits an existing file (a `package.json`, `mcp-test-client.ts`, `package-bin.spec.ts`, `publish-cli.yml`, `assert.ts`, `compiler-lock.ts`, `mcp-soak.spec.ts`, `measure-heap.ts`, a spec an earlier task created, a README, `CHANGELOG.md`, `AGENTS.md`, any `packages/language` or `packages/extension` module) is never [P] and runs in the order written.
- Each task names the files, the **failing test written first** (spec file, `describe` / `it` names, exact assertions), the implementation intent, and the **verify** command(s). Canonical order per task: failing test (run it, see it red) → implement → `pnpm check` (Biome autofix) clean → the named tests pass. Effect code (`packages/cli/src/mcp/**`, which includes `mcp/evals/**` and `compiler-lock.ts`) additionally `pnpm effect:check:cli` → `0 errors, 0 warnings and 0 messages`. Guard assertions that are green by construction (an exclusion that already holds) are proven by a one-time mutation instead: make the guarded thing wrong, see red, revert; the task says so.
- Read `specs/TESTING_GUIDE.md` before writing the first test (Constitution XXV).
- Paths: Windows backslash paths for every file tool (`F:\projects\eligius\eligian\...`); POSIX paths in Bash (`/f/projects/eligius/eligian/...`). `$SCRATCH` = the executing session's scratchpad directory, never `/tmp`. Commands run from the repo root in Bash. pnpm only. Never edit `**/generated/**` or `*.generated.ts`. No grammar change (FR-028): if any task seems to need `pnpm langium:generate`, stop with `blocked`.
- **`BASE`** = `specs/058-mcp-server/phase-5-hardening-reach/baseline/`. Raw outputs that the spec or plan says go "in `compliance.md`" are saved by the task to `BASE/<name>` (one new file per task, so [P] tasks never share a file). The comply stage quotes them, writes `compliance.md`, and only then sets the roadmap's Phase 5 status line (FR-029: "BUILT, EXIT OPEN" while SC-002 / SC-003 / SC-009 / the promotion rows wait on the user).
