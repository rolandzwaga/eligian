== Verdicts against FR-056's definition of "works" ==

Probe as the curriculum teaches it (main.eligian: addController("LottieController", "./anim.json")
in on enter, removed in on leave; lottie-web 5.13.0 installed in the project):
  compile --bundle + open the bundle : DOES NOT WORK. No <svg> in #anim; console.error
      "LottieController: provide the animation as 'json' or 'animationData'" (engine action error,
      logged by Eligius because nothing subscribes to the engine's error event).
  dev, on page load                  : DOES NOT WORK. Same console.error, no <svg>.
  smoke --strict                     : DOES NOT WORK. exit 1, smoke-engine-error with the same message.
  lottie-web not resolvable + check  : AS SPECIFIED (SC-022(1)). Exactly one diagnostic: warning
      lottie-web-not-installed at main.eligian 6:5 (the addController call), exit 0. With
      lottie-web installed: 0 diagnostics (SC-022(2)).

Why: the DSL maps addController's positional arguments onto the controller metadata parameters,
and for LottieController that list is only `url`
(packages/language/src/completion/metadata/controllers.generated.ts:110-118; transform at
packages/language/src/compiler/transformers/operation-transformer.ts:245-260), so the compiled
operation is addControllerToElement({ url: "./anim.json" }). Eligius 4.2's LottieController.init
requires `json` or `animationData` in the operation data and uses `url` only to parse
[freeze=..,end=..] (bundle.js of run 1a, LottieController.init). The animation data must come
from a preceding loadJson(url), whose `json` output stays in the operation data.

Supplementary variants (not required by T048; recorded to locate the gaps):
  loadjson.eligian (loadJson("./anim.json") before addController):
    compile --bundle, bundle as written : no <svg>; console.error "loadJson: ./anim.json responded
        404 Not Found". The bundler does not copy the file: mapConfigAssetRefs
        (packages/cli/src/bundler/asset-collector.ts:294) only covers timelineProviderSettings
        src/path and positionSource sources, not operation-data urls.
    same bundle, anim.json copied beside index.html by hand : WORKS. <svg> 56 ms after load, no
        console message, no exception, no engine error event (only the browser's favicon.ico 404
        network entry, which is not a console error).
    dev : no <svg>; anim.json 404. The dev server serves only its build output directory
        (packages/cli/src/dev/dev-server.ts:190-206).
    smoke --strict : exit 1, "loadJson: ./anim.json failed: Failed to parse URL from ./anim.json"
        (relative URL fetched by Node inside smoke).
  datauri.eligian (loadJson("data:application/json;base64,<anim.json>")):
    dev : WORKS. <svg> 31 ms after load, no console message, no engine error event.
    smoke --strict : exit 1, "LottieController requires the optional peer dependency 'lottie-web'"
        although lottie-web IS installed: imported under smoke's global jsdom window, lottie-web
        throws at module load ("Cannot set properties of null (setting 'fillStyle')": jsdom's
        HTMLCanvasElement.getContext is not implemented without the `canvas` package). A plain
        node import of lottie-web from the same project succeeds. So LottieController cannot run
        under `eligian smoke` at all; Eligius' message misattributes the cause.

Defects for triage (not fixed by T048; T048 only records):
  D-L1 addController("LottieController", url) never works at runtime: the controller needs `json`
       / `animationData`; the overlay packages/cli/src/mcp/knowledge/curriculum/controllers/LottieController.md
       (card + probe) and its "works where lottie-web resolves" claim teach the failing form.
  D-L2 --bundle and dev do not carry the animation JSON (operation-data urls are not assets;
       dev serves only the build dir).
  D-L3 smoke cannot load lottie-web under jsdom (canvas), so a Lottie program never smokes clean;
       the error says lottie-web is missing when it is installed.
